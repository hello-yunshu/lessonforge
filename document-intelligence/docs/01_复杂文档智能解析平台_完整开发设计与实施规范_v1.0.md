# 复杂文档智能解析与持续学习平台

## 完整开发设计与实施规范 v1.0

> 本文档是 `document-intelligence` 项目的研发基线，用于统一产品边界、系统架构、数据协议、领域扩展方式、Rill 接入、持续学习、评测门禁、发布回滚和阶段性交付。
>
> 核心项目必须保持通用，不得在核心 Schema、核心服务名称或核心模型协议中写入某一行业、教材版本、出版社、合同类型或其他单一业务语义。具体业务能力通过可安装、可版本化、可卸载的 Domain Pack 接入。

# 1. 项目定义

## 1.1 产品定位

`document-intelligence` 是一个面向复杂、多模态、强结构文档的通用智能解析平台。它负责把 PDF、扫描件、图片、局部截图及后续可扩展的 Office 文档，转换为：

- 可定位的页面对象；
- 可验证的文字、公式、表格、图像和版面结构；
- 可追踪的对象关系；
- 可扩展的领域语义；
- 带来源、坐标、置信度和模型版本的结构化数据；
- 可经过人工审核、持续学习和受控升级的标准结果。

平台不是单一 OCR，也不是单一大模型。它是一套由以下部分组成的复合系统：

1. 文档导入与预处理；
2. 多解析器适配；
3. 通用版面与对象识别；
4. 结构和关系恢复；
5. 标准文档匹配；
6. Domain Pack 领域适配；
7. 规则与一致性验证；
8. 人工审核与证据管理；
9. Rill 持续学习控制层；
10. 数据、模型、规则与适配包的 MLOps 生命周期。

## 1.2 核心价值

平台需要实现四个关键能力：

### A. 读准

识别文字、数字、单位、公式、表格、图形、人物、气泡、图标、栏目、页码和空间坐标。

### B. 读懂结构

恢复阅读顺序、标题层级、内容分组、图文关联、跨页连续关系和领域对象关系。

### C. 可核验

任何重要结论均可回到原文档、原页面和原区域，并可知道由哪个解析器、哪个模型、哪个规则或哪个人工审核结果产生。

### D. 越用越稳

利用人工反馈、黄金数据、多解析器分歧、漂移检测和 Rill 路由学习，持续降低严重错误和无效人工审核成本，但不得无门禁地自动修改生产真值或生产代码。

## 1.3 首个验证领域

项目核心保持通用。教育内容可作为首个高复杂度 Domain Pack，用于验证：

- 混合图文；
- 数学公式；
- 人物与气泡；
- 图标与编号；
- 跨页内容；
- 内容分组；
- 强领域关系；
- 标准文档局部匹配。

此验证领域不得反向污染核心层命名和数据协议。

# 2. 目标与非目标

## 2.1 v1.0 总体目标

1. 建立统一、稳定、可扩展的 Document Schema；
2. 接入至少两个可替换的解析器；
3. 支持 PDF、图片、扫描件和局部截图；
4. 支持文字、版面、公式、表格、图像区域和阅读顺序；
5. 支持领域适配包；
6. 支持标准文档库与局部匹配；
7. 支持人工预标注、审核、关系修正和证据回溯；
8. 完成 Rill Shadow 与 Assist 两阶段接入；
9. 建立数据、模型、规则、适配包和 Rill 状态的版本管理；
10. 形成可审计、可灰度、可回滚的发布流程。

## 2.2 明确非目标

v1.0 不追求：

- 让一个大模型端到端完成全部识别；
- 对所有文档类型零样本达到生产级准确率；
- 让终端用户反馈直接修改黄金数据；
- 让 Rill 自动修改生产代码；
- 让候选模型未经离线门禁直接替换正式模型；
- 用生成文本代替原文档证据；
- 为每一本、每一份文档训练独立完整模型；
- 把某一领域语义固化进核心 Schema。

# 3. 总体设计原则

## 3.1 Runtime-first，Agent 薄化

- 通用解析能力位于主系统；
- 在线学习算法位于 `rill-ml`；
- Observe/Decide/Feedback、状态和快照位于 `rill-runtime`；
- 领域无关的 Rill 业务桥接位于 `document-rill-agent`；
- Domain Pack 只提供领域特征、规则、验证器和轻量适配参数。

`document-rill-agent` 不得复制解析器、数据库或训练平台功能。

## 3.2 确定性优先，生成式模型兜底

处理优先级：

1. 原生 PDF 结构提取；
2. 标准文档页和局部指纹匹配；
3. OCR、版面模型和规则系统；
4. 第二解析器交叉校验；
5. 视觉语言模型疑难复核；
6. 人工审核。

越靠后的处理成本越高，仅处理前面无法安全解决的样本。

## 3.3 已知文档优先调用标准结果

对于已经入库并审核完成的标准文档：

- 用户上传整页或局部截图时，优先做身份和区域匹配；
- 匹配达到门禁后，直接调用已审核标准结果；
- 不得每次重新生成该页面的结构化内容；
- 解析器只负责确定裁剪、缩放、旋转和局部区域映射。

## 3.4 核心对象与领域对象分层

核心层只认识：

- Document；
- Page；
- Region；
- Element；
- Relation；
- Evidence；
- ParseRun；
- ReviewRecord。

领域层才能声明：例题、合同条款、论文摘要、试卷选项等业务概念。

## 3.5 任何自动升级都必须可回放、可比较、可回滚

- 数据集不可原地覆盖；
- 模型不可覆盖旧版本；
- 规则包不可无版本发布；
- Domain Pack 必须声明兼容范围；
- Rill 状态必须可快照和重置；
- 发布前必须运行固定黄金集和挑战集。

# 4. 推荐开源组件与职责

## 4.1 主解析器：PaddleOCR / PP-StructureV3

建议职责：

- 中文和多语言 OCR；
- 文本检测与识别；
- 版面解析；
- 公式、表格和图片区域；
- Markdown / JSON 等结构化结果；
- 自定义版面模型训练基础。

使用原则：

- 通过适配器调用，不让业务服务直接依赖私有输出结构；
- 首次基线评测后锁定明确版本和模型文件哈希；
- 升级必须重新运行黄金集；
- 对关键数字和单位不得只依赖单一平均置信度。

官方项目：<https://github.com/PaddlePaddle/PaddleOCR>

## 4.2 第二解析器：OpenOCR / OpenDoc-0.1B

建议职责：

- 提供低成本第二意见；
- 对主解析器低置信页面复核；
- 提供模型分歧信号；
- 在部分文字、公式或表格场景中作为候选主路由。

使用原则：

- 不默认全量双跑；
- 由静态规则或 Rill Route 选择是否调用；
- 输出必须转换为统一 Schema；
- 是否进入正式生产依据自有测试集，不依据项目宣传指标。

官方项目：<https://github.com/Topdu/OpenOCR>

## 4.3 标注与审核：LabelU / LabelU-Kit

建议职责：

- 对象框、分割和关键点标注；
- AI 预标注后的人工修正；
- 人物—气泡、图—文字等关系标注；
- 审核工作台的基础组件；
- COCO 和自定义关系 JSON 导出。

使用原则：

- 通过 LabelU-Kit 嵌入自有审核界面；
- 黄金数据必须保留审核人、时间、修订原因；
- 终端用户反馈与专家审核必须分库存储。

官方项目：

- <https://github.com/opendatalab/labelU>
- <https://github.com/opendatalab/labelU-Kit>

## 4.4 对照基线：MinerU

建议职责：

- 复杂 PDF 整体恢复对照；
- Markdown / JSON 基线；
- 公式、表格、阅读顺序和跨页场景的横向测试。

限制：

- 不作为不可替换的核心依赖；
- 产品化前必须单独审核许可证和附加条款；
- 仅通过 `MinerUBenchmarkParser` 适配器接入。

官方项目：<https://github.com/opendatalab/MinerU>

## 4.5 数据与模型生命周期

- DVC：数据集、训练输入和流水线版本；
- MLflow：实验记录、指标、产物、模型注册和别名；
- PostgreSQL：标准结构数据、审核、版本和关系；
- S3 兼容对象存储：原文件、页面图像、模型、训练产物；
- FAISS 或 pgvector：相似页面和区域召回；
- Prometheus + Grafana：运行指标和告警；
- OpenTelemetry：跨服务追踪。

官方项目：

- <https://dvc.org/>
- <https://mlflow.org/docs/latest/ml/model-registry/>

# 5. 逻辑架构

```text
文档输入
  ↓
Ingestion：格式检测、文件指纹、页拆分
  ↓
Preprocessing：纠偏、去噪、裁剪、方向、清晰度
  ↓
Identity & Matching：标准文档匹配、页面和局部区域召回
  ↓
Parser Router
  ├─ Native PDF Parser
  ├─ Paddle Parser
  ├─ OpenDoc Parser
  ├─ Formula / Table Specialist
  └─ Optional VLM Review
  ↓
Normalization：统一 Document Schema
  ↓
Structure：阅读顺序、分组、跨页和关系恢复
  ↓
Domain Runtime：加载 Domain Pack
  ↓
Validation：通用规则、领域规则、整文档一致性
  ↓
Rill Observe / Decide
  ↓
ACCEPT / RETRY / SECONDARY / VLM / HUMAN / QUARANTINE
  ↓
Review & Feedback
  ↓
标准结果、训练候选、漂移信号、版本化产物
```

## 6.3 仓库边界

### `document-intelligence`

拥有：

- 文档解析；
- 标准文档库；
- Domain Pack；
- 审核系统；
- 评测；
- 训练与模型发布接口。

### `rill-ml`

拥有：

- LinUCB 或其他上下文路由算法；
- Page-Hinkley、ADWIN、KSWIN 等漂移检测；
- 在线指标和策略状态；
- 算法级序列化。

不得拥有：

- 具体文档类别；
- 解析器 SDK；
- 某个领域规则；
- 生产数据库访问。

### `rill-runtime`

拥有：

- 会话与状态；
- Observe / Decide / Feedback；
- Inspect / Snapshot / Reset；
- 策略版本和恢复语义。

### `document-rill-agent`

拥有：

- 把解析结果转换为 Rill 特征；
- 把 Rill 决策映射为允许动作；
- 动作安全门禁；
- 结果验证；
- 反馈回传；
- 审计事件。

不得拥有：

- 任意 Shell 执行；
- 生产模型发布权限；
- 黄金数据写权限；
- 无边界自动修改配置能力。

```json

  "x1": 0.12,
  "y1": 0.30,
```

# 9. Domain Pack 规范

## 9.1 目录格式

```text
domain-pack-name/
├── manifest.yaml
├── ontology.yaml
├── labels.yaml
├── dictionaries/
├── templates/
├── rules/
├── validators/
├── model-adapters/
├── migrations/
└── evaluation/
```

## 9.2 manifest 示例

```yaml
id: education-content
version: 0.1.0
core_schema: ">=1.0,<2.0"
supported_languages: [zh-CN]
capabilities:
  - object-classification
  - relation-recovery
  - standard-document-matching
entrypoints:
  rules: rules/main.yaml
  validator: validators.main:validate
```

## 9.3 领域扩展方式

Domain Pack 可以：

- 把通用对象映射为领域对象；
- 增加领域属性；
- 增加关系类型；
- 提供词典、模板和版式族；
- 加载轻量模型适配参数；
- 提供领域级校验器；
- 提供领域黄金集。

Domain Pack 不可以：

- 修改核心表结构；
- 覆盖核心对象含义；
- 跳过证据链；
- 直接写入黄金数据；
- 绕过 Rill 和发布门禁执行生产动作。

# 10. 标准文档库与局部匹配

## 10.1 入库产物

每一页生成：

- 原始页面图像；
- 多分辨率缩略图；
- SHA-256；
- 感知哈希；
- OCR 规范化文本；
- 文本 n-gram；
- BM25 索引；
- 页面向量；
- ORB/局部图像特征；
- 布局摘要；
- 相邻页关系；
- 已审核标准结构。

## 10.2 多路召回

```text
身份或 Domain Pack 过滤
+ 感知哈希
+ OCR/BM25
+ 模糊文本匹配
+ 页面向量
+ 局部图像特征
+ 布局相似度
+ 相邻页一致性
```

## 10.3 匹配门禁

- Top-1 分数超过高阈值且与 Top-2 有足够间隔：调用标准结果；
- Top-1 较高但候选接近：第二模型或人工确认；
- 低分：按未知文档进入通用解析；
- 不允许只用文件名或页码判断身份。

## 10.4 局部截图

局部截图必须输出：

- 最佳页面候选；
- 匹配区域；
- 仿射或透视变换；
- 候选列表；
- 匹配证据；
- 是否可安全调用标准结果。

# 12. Rill 集成设计

## 12.1 定位

Rill 是持续学习和策略控制层，不是 OCR、版面识别器或训练框架。

Rill 主要负责：

- 选择解析路线；
- 识别漂移和异常；
- 判断是否需要第二解析器；
- 调整送审优先级；
- 发现高价值训练样本；
- 形成候选训练或适配任务；
- 评估路由策略效果；
- 保存在线状态和延迟反馈。

## 12.2 三个逻辑模块

### Sentinel

监控：

- 输入质量变化；
- OCR 置信度变化；
- 模型分歧上升；
- 规则冲突上升；
- 人工修正率上升；
- 新版式族；
- 版本串用和匹配异常；
- 模型服务错误和延迟异常。

### Doctor

归因：

- 输入质量；
- OCR；
- 版面；
- 公式或表格专家；
- Domain Pack；
- 规则；
- 标准文档库缺失；
- 模型升级回归；
- 人工标注不一致。

### Route

可选择：

- `ACCEPT`
- `RETRY`
- `REPROCESS_HIGH_RES`
- `USE_SECONDARY_PARSER`
- `USE_SPECIALIST_PARSER`
- `USE_DOMAIN_ADAPTER`
- `VLM_REVIEW`
- `HUMAN_REVIEW`
- `QUARANTINE`

## 12.6 奖励函数原则

不能只优化自动通过率。建议：

```text
reward
= correctness_gain
- critical_error_penalty
- human_review_cost
- inference_cost
- latency_penalty
- instability_penalty
```

严重错误必须使用远高于普通错误的惩罚，包括：

- 关键数字错误；
- 单位错误；
- 对象归属错误；
- 关系错绑；
- 标准文档误匹配；
- Domain Pack 串用；
- 已审核结果被错误覆盖。

## 12.7 动作等级

### Tier 0：观察

- 指标采集；
- 漂移检测；
- 生成建议；
- 离线回放；
- 样本优先级排序。

### Tier 1：低风险 Assist

- 选择第二解析器；
- 高分辨率重处理；
- 调用专用公式或表格模型；
- 调整审核优先级；
- 暂停异常解析器；
- 进入隔离队列。

### Tier 2：候选升级

- 创建候选训练任务；
- 生成候选规则；
- 生成候选 Domain Pack；
- 运行离线回放；
- 注册 Candidate。

### Tier 3：正式发布

必须人工批准：

- 发布正式模型；
- 发布 Domain Pack；
- 修改黄金数据；
- 修改核心 Schema；
- 扩大自动动作范围；
- 更改关键阈值上限。

## 12.8 当前安全要求

在 Rill 自身尚未通过正式冻结审计前：

- Route 首先运行 Shadow；
- Assist 仅开放 Tier 1 白名单动作；
- boundedAuto 保持硬禁用；
- 任何动作必须幂等；
- 所有决策和执行结果必须进入审计日志；
- Rill 故障时回退到静态安全策略，不阻塞基础解析。

# 13. 人工审核与数据治理

## 13.1 审核等级

```text
终端用户反馈 → 待复核池
普通审核员确认 → 正式训练数据
领域专家确认 → 黄金数据
```

## 13.2 黄金数据规则

- 只追加版本，不原地覆盖；
- 修订必须有原因；
- 关键样本建议双人复核；
- 模型和 Rill 不得拥有直接写权限；
- 黄金集不得用于训练后再作为唯一测试集；
- 按文档族、输入质量和困难类型分层。

## 13.3 主动学习

优先送审：

- 多解析器分歧；
- 规则冲突；
- 新版式；
- 低置信度；
- 高严重度候选；
- 人工修改时间高；
- 重复高频错误；
- 漂移检测触发样本。

Rill 负责排序，不负责将结果直接升级为真值。

# 14. 模型训练与 MLOps

## 14.1 版本对象分离

必须独立管理：

- 核心引擎版本；
- 解析器适配器版本；
- OCR 模型版本；
- 通用版面模型版本；
- 领域模型版本；
- Domain Pack 版本；
- 规则包版本；
- 标准文档数据版本；
- 黄金集版本；
- Rill 策略版本；
- Rill 状态快照版本。

## 14.2 模型生命周期

```text
训练任务
→ DVC 数据快照
→ 训练
→ MLflow 实验
→ 黄金集与挑战集
→ 注册 Candidate
→ Shadow
→ 小流量灰度
→ 人工批准
→ Champion
→ 监控
→ 保留 Rollback
```

## 14.3 发布别名

建议：

- `champion`
- `candidate`
- `shadow`
- `rollback`

生产配置引用别名，不直接写死任意文件路径。

## 14.4 升级门禁

候选版本必须满足：

1. 历史黄金集无关键指标回退；
2. 新文档挑战集有可验证提升；
3. 严重错误率不增加；
4. 标准文档误匹配率不增加；
5. 关键数字、单位和关系准确率不下降；
6. 推理延迟和成本在预算内；
7. 无明显文档族偏置；
8. 可在规定时间内回滚；
9. 模型、数据和配置哈希完整；
10. 评测结果可复现。

# 15. 评测体系

## 15.1 识别层

- CER / WER；
- 数字准确率；
- 单位准确率；
- 公式结构准确率；
- 表格单元格准确率。

## 15.2 对象层

- Precision / Recall / F1；
- mAP；
- 小对象召回；
- 关键对象漏检率；
- 坐标 IoU。

## 15.3 结构层

- 阅读顺序准确率；
- 分组准确率；
- 标题层级准确率；
- 跨页恢复准确率；
- 图注和图片绑定准确率。

## 15.4 关系层

- 关系分类 F1；
- 错绑率；
- 漏绑率；
- 关键关系准确率；
- 图结构一致性。

## 15.5 匹配层

- 标准文档 Top-1 / Top-5；
- 局部区域定位 IoU；
- Top-1 与 Top-2 间隔分布；
- 错误调用标准结果率；
- 未知文档误判为已知文档率。

## 15.6 运营层

- 单页延迟；
- 单页推理成本；
- 自动通过率；
- 人工审核率；
- 人工平均修改时间；
- 二次解析命中率；
- Rill 决策正确率；
- 漂移发现提前量。

## 15.7 关键门禁指标

不得用一个“总准确率”代替以下指标：

- 严重错误率；
- 关键值准确率；
- 标准文档误匹配率；
- Domain Pack 串用率；
- 已审核结果被覆盖率；
- 人工无效送审率。

# 18. 安全、隐私与许可证

## 18.1 文件安全

- 上传文件先进入隔离区；
- 检查 MIME 与实际内容；
- 限制页数、尺寸和解压比；
- 禁止任意宏和脚本执行；
- 渲染在受限容器中完成。

## 18.2 数据权限

角色至少包括：

- viewer；
- reviewer；
- expert-reviewer；
- domain-pack-maintainer；
- model-release-manager；
- platform-admin。

模型和 Rill 服务账户不得拥有专家黄金数据直接写权限。

## 18.3 审计

必须记录：

- 谁上传；
- 谁审核；
- 谁修改；
- 使用哪个模型；
- Rill 做了什么决策；
- 是否执行；
- 执行结果；
- 发布和回滚人。

## 18.4 许可证

每个第三方组件必须登记：

- 代码许可证；
- 模型权重许可证；
- 商业使用限制；
- 再分发要求；
- NOTICE 要求；
- 依赖版本和哈希。

MinerU 等带附加许可条件的组件只能作为可替换对照项，未经法律和商业审核不得成为核心生产依赖。

# 23. 关键风险与应对

## 风险一：过早依赖大模型

应对：确定性解析、标准文档匹配和规则优先；VLM 只处理疑难项。

## 风险二：核心层被首个领域污染

应对：核心 Schema 审查；Domain Pack 合约测试；禁止领域术语进入核心 API。

## 风险三：自动学习污染真值

应对：反馈分级；专家黄金集只读；Rill 无黄金写权限。

## 风险四：多模型结果难以比较

应对：统一 Schema、统一评测、固定输入和配置哈希。

## 风险五：模型升级表面提升、关键任务退步

应对：分层门禁，关键数字、关系和误匹配独立指标。

## 风险六：Rill 自动动作越权

应对：动作白名单、Tier 分级、幂等执行、boundedAuto 关闭、审计和回退。

## 风险七：第三方许可证阻碍产品化

应对：依赖清单、代码和权重许可证分别审核、核心依赖可替换。

# 24. 架构决策摘要

1. 不训练单一端到端大模型作为整个系统；
2. PaddleOCR / PP-StructureV3 作为首选主基线；
3. OpenDoc-0.1B 作为第二解析器候选；
4. LabelU-Kit 作为审核界面基础；
5. MinerU 只做可替换的效果对照；
6. 已知文档优先匹配并调用标准结果；
7. 核心 Schema 保持领域无关；
8. 领域能力全部进入 Domain Pack；
9. Rill 负责路由、漂移、反馈和候选升级，不直接修改真值和生产代码；
10. Rill 必须从 Shadow 开始，Assist 只开放低风险白名单；
11. 数据、模型、规则、Domain Pack、Rill 状态分别版本化；
12. 所有正式升级必须经过黄金集、Shadow、灰度和回滚门禁。

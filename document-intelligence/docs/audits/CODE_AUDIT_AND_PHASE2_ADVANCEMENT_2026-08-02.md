# 0.1.0 复审与 Phase 2 推进审计

## 1. 审核方式

本次没有沿用上一份自述性审计结论，而是从 Phase 1 ZIP 和当前源码重新检查：

- 运行标识与请求上下文；
- 路径和符号链接边界；
- 原文件、二进制资产和原始输出留存；
- 已提交运行的落盘完整性；
- 外部解析器响应、版本和模型摘要门禁；
- 标准文档入库、索引、匹配和安全复用；
- API访问边界；
- 并发写入、失败记录和分发安装；
- 测试、覆盖率、阶段脚本和独立打包。

## 2. 原 0.1.0 冻结结论

原 0.1.0 **不能作为冻结版本继续发布**。主要阻断项如下。

| 级别 | 问题 | 风险 | 处理结果 |
|---|---|---|---|
| P0 | 外部解析器返回的运行ID可能被用于越出运行目录 | 路径越界与跨运行污染 | 所有标识在Schema和存储边界双重校验 |
| P0 | 同一内容在不同文件名、领域包或配置下可能发生运行ID碰撞 | 不同请求共享错误结果 | 运行ID绑定文件名、领域包、配置、解析器实现和请求上下文摘要 |
| P0 | 原始上传文件和嵌入二进制资产未完整留存 | 结果无法审计和重放 | 引入内容寻址 `sources/`、`assets/` 和原子运行提交 |
| P0 | 运行读取只做Schema解析，不验证落盘摘要 | 文件被篡改后仍可能被读取 | 运行清单绑定并复核run、document、raw和source摘要 |
| P0 | 失败记录使用可重复ID | 重试会覆盖失败证据 | 每次失败绑定独立发生时间和唯一记录 |
| P1 | PDF页数、渲染像素、元素和外部响应缺少统一上限 | 内存和磁盘资源失控 | 增加输入、页面、像素、元素、资产和响应体上限 |
| P1 | 外部网关对非对象JSON、异常Content-Length处理不足 | 合约绕过或内存风险 | 健康与解析响应流式限长，非对象JSON直接拒绝 |
| P1 | 包内默认配置依赖当前工作目录 | wheel安装后可能失效 | 默认解析器配置作为包数据随wheel分发 |

修复后，Phase 1功能保留，但版本线推进为0.2.0，不再把0.1.0称为可冻结交付。

## 3. Phase 2 新增实现

### 3.1 标准文档库

- 标准结果只能由成功运行经过显式人工审核后注册；
- `DI_ENABLE_STANDARD_WRITES`默认关闭；
- 标准管理和标准正文返回使用 `X-Standard-Token`；
- 服务端只保存访问令牌的SHA-256，未配置时默认拒绝；
- 标准版本目录不可原地覆盖；
- 标准结构文件、页面指纹、缩略图和特征文件分别绑定摘要；
- 标准结构读取时交叉验证文档身份、来源、Schema和语义摘要。

### 3.2 页面指纹和匹配

- 页面PNG、缩略图、dHash、文本n-gram、布局摘要；
- ORB关键点、描述子和RANSAC几何验证；
- 全页和局部截图匹配；
- Top-1分数、Top-2间隔和几何证据联合门禁；
- 强局部特征不能绕过配置总分阈值；
- 重复页面进入 `ambiguous`，未知页面进入 `no_match`；
- 只有 `safe_standard_reuse` 能引用标准结果。

### 3.3 可复现性与完整性

匹配结果现在记录：

- 匹配器版本与源码摘要；
- 指纹流水线摘要；
- 标准索引摘要；
- 查询页码；
- 所有阈值和局部内点门禁。

标准索引同时绑定全部标准清单摘要，新增或修改标准清单后旧索引会被判定为过期并拒绝使用。

### 3.4 并发和文件系统安全

- 标准索引重建使用独占锁；
- 锁文件包含进程和随机令牌；
- 仅确认超时且原进程不存在时清除遗留锁；
- 释放锁前验证令牌，避免删除其他进程新建的锁；
- 运行和标准库关键路径拒绝符号链接；
- 临时目录完成后再原子发布。

## 4. Rill边界

Phase 2只扩展Rill Observe事件，继续强制：

```json
{"shadow_only": true}
```

Rill可以观察匹配结果、候选间隔、规则冲突和人工反馈，但不得：

- 写入标准库；
- 自动修改匹配阈值；
- 自动发布模型或适配包；
- 启用Route Assist或boundedAuto；
- 修改黄金数据。

## 5. 验证结果

- 自动测试：67项全部通过；
- 分支覆盖率：80.66%，达到项目80%门禁；
- Python源码、测试和脚本编译通过；
- Phase 1验证门禁通过；
- Phase 2验证门禁通过；
- wheel构建、包内默认配置、任意工作目录导入和CLI冒烟通过；
- 本地确定性静态门禁通过，共检查53个Python文件；
- 小型合成匹配回归9/9通过；
- 已知页回归召回100%；
- 未知及重复页错误安全复用为0。

上述匹配数据只代表项目内小型合成回归集，不构成真实行业文档准确率声明。

## 6. 尚未完成的生产资格

以下事项仍是明确门禁，而不是被“测试通过”掩盖：

1. PaddleOCR、OpenDoc和MinerU没有在本环境固定真实模型或镜像摘要并完成资格测试；
2. 真实扫描、拍照、透视、阴影、遮挡、压缩和跨版本黄金集尚未建立；
3. PyMuPDF的AGPL/商业双重许可尚未完成产品发行选择；
4. Ruff和Mypy已固定在项目CI配置中，但当前离线环境无法安装执行，因此本地不宣称这两项通过；
5. 尚未完成百万页级索引、并发写入和长时间稳定性压力测试；
6. Rill继续只运行Shadow。

## 7. 最终判断

- 原0.1.0：冻结不通过；
- 修复后的Phase 1基础：通过；
- Phase 2标准文档匹配工程实现：通过；
- 0.2.0作为下一阶段开发基线：通过；
- 无条件生产发布：不通过，必须完成第6节门禁。

下一阶段可以进入通用结构恢复，但不得在真实生产环境扩大自动标准结果复用范围。

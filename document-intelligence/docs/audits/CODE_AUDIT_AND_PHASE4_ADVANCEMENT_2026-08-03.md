# 0.3.0 复审与 Phase 4 推进报告

## 审核基线

本轮从 Phase 3 完整 ZIP 独立解压，不信任上一轮工作目录状态。首先复跑 Phase 1—3 测试和
门禁，再依据总体开发规范确认下一阶段为 Phase 4 Domain Pack Runtime。

## Phase 3 遗留修复

发现 CLI 测试曾依赖旧绝对路径的问题已在上一阶段修复。本轮新发现的跨阶段缺陷是服务包
初始化存在循环导入，只有直接运行 Domain Runtime 或从 wheel 的任意工作目录导入时才会
触发。已改为延迟加载 bootstrap，避免测试导入顺序掩盖分发缺陷。

## Phase 4 审计重点

- 适配包是否可执行任意代码；
- ZIP 安装是否存在路径越界、特殊文件和资源耗尽风险；
- 同版本内容是否可被覆盖；
- 签名是否在每次读取时重新验证；
- 领域结果是否能污染通用结果；
- 异常是否泄露内部信息；
- 运行时升级是否破坏历史结果；
- 卸载是否破坏结果血缘；
- 审核数据是否可被越界读取或半写入；
- API 是否默认关闭管理与写入；
- Rill 是否仍被限制在 Shadow。

## 审核结论

Phase 4 工程实现通过，自审中确认的问题均已修复并新增回归。当前包可以作为 Phase 5 开发
基线，但不应描述为生产就绪，原因包括真实领域黄金集、签名密钥治理、规模压力测试、外部
解析器资格和 PyMuPDF 发行许可仍未完成。

## 不允许后续回退的边界

1. 核心 Schema 不加入特定领域对象；
2. Domain Pack 不加载任意代码；
3. 适配失败不产生领域断言；
4. 历史结果引用的包不可卸载；
5. 用户反馈不能直接成为黄金数据；
6. Rill 保持 `shadow_only=true`；
7. 模型、规则或包升级不得绕过完整黄金集回放和人工批准。

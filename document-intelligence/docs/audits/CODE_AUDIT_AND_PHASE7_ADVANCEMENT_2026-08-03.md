# Phase 6复审与Phase 7推进审计

## 基线复审

Phase 6 已具备真实Rill IPC v3宿主适配、Shadow、延迟反馈、漂移和资格受控Tier 1动作，可作为持续学习信号源。但它没有数据版本、训练运行血缘、模型候选注册、黄金/挑战门禁、灰度证据、Champion别名和回滚状态机，因此不能直接形成模型升级闭环。

## 本轮推进

新增独立 `mlops` 核心：主动学习、DVC快照、MLflow运行证明、Candidate注册、离线评测、Shadow验证、人工批准、Champion和Rollback。所有状态均不可变或通过原子别名信封更新。

## 关键审计判断

- DVC/MLflow接入是血缘证明，不是信任外部字符串；
- 训练数据、黄金集和挑战集必须角色隔离且摘要互斥；
- Candidate不能凭单一总分通过，P0/P1、严重错误、标准误匹配、关系、延迟和成本均独立设门；
- Shadow别名不等于通过灰度，必须有样本量、漂移和质量证明；
- Champion需要新的人工批准；
- 回滚优先于自动修复，Rollback别名必须在Champion切换时同步保存；
- 主动学习只决定“先看哪些”，不决定“正确答案是什么”；
- boundedAuto继续硬禁用。

## 结论

0.7.0满足Phase 7工程冻结条件，可作为Phase 8开发基线；没有真实外部数据、模型和批准时，不得宣称生产模型已发布。

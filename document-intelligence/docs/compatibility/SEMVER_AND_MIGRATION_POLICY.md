# 1.x版本、兼容与迁移政策

## 稳定基线

`document-intelligence 1.0.0` 是首个工程契约冻结版本。冻结清单位于：

- `src/document_intelligence/defaults/frozen_contracts_v1.json`
- `docs/phase-9/FROZEN_CONTRACTS_V1.json`

两个文件必须逐字节一致。清单由10类机器可验证契约组成。

## 版本语义

- **Patch（1.0.x）**：不得改变任何已冻结契约；仅允许缺陷修复、测试、文档和不改变外部行为的内部重构。
- **Minor（1.x.0）**：可新增隔离能力，但不得删除或修改已冻结Schema、SDK符号、Rill事件、权限默认值、既有REST操作、回滚保证或审计格式。
- **Major（2.0.0）**：允许不兼容调整，但必须提供迁移规范、兼容读取期、回滚方案和新的冻结清单。

当前实时版本必须满足 `>=1.0.0,<2.0.0` 才能通过v1冻结验证。

## 持久化兼容

历史记录中的 `0.5`、`0.6`、`0.7`、`0.8` 等子系统Schema版本不会因为项目进入1.0而被批量重写。1.0冻结的是其已经存在的线格式和读取语义。任何迁移必须：

1. 保留原始记录和摘要；
2. 生成新的不可变迁移记录；
3. 显式记录源版本、目标版本和迁移器摘要；
4. 支持在迁移失败时继续读取旧记录；
5. 不把迁移后的推断覆盖为原始真值。

## 冻结清单变更

1.x内不得通过重新运行生成脚本覆盖冻结清单。`scripts/generate_freeze_manifest.py` 默认只校验实时契约；初始化写入只能在不存在同一稳定主版本清单时执行。

发生不兼容需求时，应建立2.0迁移计划，而不是修改v1摘要。

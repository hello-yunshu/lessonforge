# Phase 12：Release Candidate Hardening 实施与自审

## 1. 结论

本阶段将项目推进至 `1.0.3-rc.1`。该版本通过工程发布候选门禁，可作为受限、
单节点、自托管试用候选；它不是生产稳定版，也不包含任何 `qualified=true` 生产资格
记录。

## 2. 设计目的

Phase 12不增加新的解析领域或自动化等级，而是关闭发布就绪审计中的主要工程缺口：

- 核心API默认暴露与跨租户访问风险；
- 项目发行许可证缺失；
- Native PDF基础能力与可选渲染许可耦合；
- 当前CI、Makefile和发布脚本停留在旧阶段；
- 构建、依赖、SBOM、测试时限和备份恢复证据不足；
- 能力状态与真实生产资格边界表达不充分。

## 3. 已实施

### 3.1 安全边界

生产档对全部 `/v1` 路径统一要求租户令牌、租户ID和主体ID。核心衍生资源通过不可变
entitlement记录授权；同一内容寻址结果可分别授权给不同租户，但直接猜测另一租户的
`run_id`、`structure_id`、`domain_result_id`或Rill评估ID会返回404。

同时增加：

- 每租户固定窗口请求限流；
- 每租户并发上限；
- 请求硬超时；
- 不可变访问审计；
- 生产档关闭OpenAPI和交互文档；
- 指标端点独立令牌；
- 单节点模式启动硬门禁。

### 3.2 可观测性

新增 `/livez`、`/readyz`、`/metrics` 和 `/v1/capabilities`。请求日志为结构化JSON，
包含请求ID、租户、主体、路径类别、状态码和耗时，不记录明文令牌或文档正文。

### 3.3 PDF与许可证

Base `NativePdfParser`改用 `pypdf` 提取原生文字和嵌入图像。PyMuPDF仅保留为可选
像素渲染器，用于标准页视觉指纹和PDF查询页渲染：

- base wheel不依赖PyMuPDF；
- 生产compose默认 `DI_PDF_RENDER_BACKEND=disabled`；
- 启用PyMuPDF时生产配置必须同时提供许可证已解决证明；
- 未启用时相关视觉PDF能力明确失败，不回退为伪成功。

### 3.4 发行与供应链

- 添加Apache-2.0 `LICENSE`、`NOTICE`、`SECURITY.md`、`SUPPORT.md`；
- 直接依赖和开发工具使用精确版本；
- 添加安装树摘要登记、SPDX 2.3 SBOM和密钥扫描；
- 唯一CI执行Phase 1—12、Ruff、Mypy、测试时限、覆盖率和pip-audit；
- GitHub Actions引用固定提交；
- Docker构建要求调用方提供digest-pinned基础镜像；
- Compose默认只绑定宿主回环地址，丢弃Linux capabilities并限制资源；
- 添加确定性完整源码ZIP和两次归一化wheel一致性检查；
- 添加工作区备份、校验与空目录恢复工具。

## 4. 实施后自审发现与修复

1. entitlement时间戳经Pydantic规范化后摘要不一致；已统一UTC `Z`格式。
2. 开发档PDF视觉匹配被安全默认意外关闭；已保持开发兼容，生产compose仍默认关闭。
3. 生产路径中存在依赖Python `assert`的运行校验；已替换为显式失败异常。
4. 仅移除PyMuPDF顶层导入仍不足以形成许可隔离；已把base解析器改为pypdf，并增加
   renderer策略门禁。
5. pyproject同时使用PEP 639 license表达和旧license classifier导致wheel构建失败；
   已按当前元数据规范修正。
6. entitlement有租户记录但没有读取时完整性测试；已加入篡改检测回归。
7. 原测试总入口缺少硬时限；已拆为四批，每批120秒，并记录真实执行证据。
8. 子进程输出管道可能被Rill测试子进程继承；正式CI改为shell级 `timeout`，避免等待
   管道关闭造成假挂死。
9. pyproject曾指向不存在的公开源码仓库；已删除未验证URL，安全策略要求发行方配置
   私有报告渠道。
10. Docker生产构建若没有基础镜像摘要应直接失败；已取消不安全默认基础镜像。

## 5. 验证结果

- 自动测试：241项全部通过；
- 测试文件：57个，分4批执行；
- 批次累计墙钟时间：60.24秒；
- 综合覆盖率：80.26%；
- 语句覆盖率：84.80%；
- 分支覆盖率：63.87%；
- Phase 1—12基准和验证：全部通过；
- Phase 12确定性发布候选基准：10/10通过；
- Python `-O`优化模式验证：通过；
- 静态安全检查：通过；
- 密钥扫描：通过；
- wheel独立安装与任意目录导入：通过；
- 1.x冻结清单：保持兼容。

综合覆盖率超过80%不等于分支覆盖率超过80%。本报告明确保留63.87%的真实分支覆盖
结果，不通过四舍五入掩盖错误分支测试不足。

## 6. 尚未完成

当前离线环境没有Ruff、Mypy、pip-audit和CycloneDX正式工具，因此这些工具只在唯一CI
中作为强门禁，本地不声明通过。正式稳定发布仍需：

- CI真实成功记录和漏洞/容器扫描报告；
- 发行方选定并验证digest-pinned基础镜像；
- 真实黄金集、挑战集和外部解析器固定产物；
- 168小时持续运行与规模恢复证据；
- 可选PyMuPDF渲染器的许可证证明；
- 真实试运行和独立批准；
- 关键存储与API错误分支覆盖提升。

## 7. 冻结判断

`1.0.3-rc.1`可作为下一轮真实部署演练的候选包。不得标记为生产稳定版，不得打开
`boundedAuto`，不得把Reference Rill、未固定外部解析器或合成资格数据描述为生产能力。

# Phase 4 实施、冻结与自审报告

## 1. 阶段结论

Phase 4 已完成 **Domain Pack Runtime** 的工程实现。项目版本由 `0.3.0` 升级到
`0.4.0`。本阶段把 Phase 3 输出的通用结构结果转换为可选的领域结果，同时保证：

1. 核心文档 Schema 与结构引擎保持领域中立；
2. Domain Pack 不能执行任意 Python 代码；
3. 领域结果与通用解析、通用结构分开持久化；
4. 适配失败时只能回退到通用结构，不能产生领域断言；
5. 安装、启用、停用、历史读取、审核和卸载均有完整性门禁；
6. Rill 只接收可审计的 Phase 4 质量信号，仍固定为 Shadow。

Phase 4 工程冻结通过，可作为 Phase 5 Rill Shadow 的开发基线。真实领域准确率、
高并发、正式签名密钥治理和生产许可证问题尚未完成，因此不构成无条件生产发布。

## 2. 实现范围

### 2.1 Domain Pack SDK

新增统一清单和声明式资源模型：

- `manifest.yaml`：ID、版本、核心 Schema 范围、引擎范围、能力、权限、入口和摘要；
- `ontology.yaml`：领域对象及关系定义；
- `rules/*.yaml`：对象分类和关系恢复规则；
- `validators/*.yaml`：必需对象与关系端点约束；
- `review/*.yaml`：审核工具标签配置；
- `labels.yaml`：可选显示标签和术语。

入口文件只允许 YAML、YML 或 JSON。运行时不会导入或执行适配包内的 Python、Shell、
动态库或模板表达式。这是本阶段的主要隔离边界。

### 2.2 安全安装与不可变注册表

`DomainPackRegistry` 实现：

- ZIP 与目录安装；
- 路径穿越、绝对路径、符号链接、特殊文件和加密 ZIP 拒绝；
- 文件数量、压缩包大小、展开大小和压缩比上限；
- 每个文件 SHA-256 与清单严格一致；
- 可选 Ed25519 签名及可信公钥表；
- 核心 Schema 与运行时版本兼容性检查；
- 同 ID、同版本、不同内容冲突拒绝；
- 不可变版本目录；
- 启用、停用、列表和卸载；
- 注册表锁、过期锁处理和原子状态写入；
- 已被领域结果引用的版本禁止卸载。

历史结果读取和旧包枚举不会因为当前运行时兼容范围变化而失效，但新执行和重新启用仍
必须满足当前兼容范围。历史签名密钥必须保留在可信密钥环中，密钥治理属于生产部署要求。

### 2.3 声明式领域运行时

`DomainRuntimeEngine` 根据通用 `ParsedDocument` 与 `StructureResult` 执行：

- 基础类型筛选；
- 文本前缀、包含词和文本存在性条件；
- 领域对象标注；
- 基于已有通用关系和有界阅读距离的领域关系恢复；
- 必需对象验证；
- 领域关系端点验证；
- 证据覆盖率、对象数量、关系数量及发现数量统计。

所有领域对象和关系都必须绑定来源证据。运行时不得修改通用文档或结构对象。

### 2.4 失败隔离

领域执行异常默认生成 `fallback_generic` 结果：

- 领域对象列表为空；
- 领域关系列表为空；
- 通用结构通过响应显式返回；
- 原始异常文本不写入客户端可见结果；
- 失败代码和脱敏说明可用于 Rill、审核及运维统计；
- 禁用回退时，异常被包装为稳定的 `DomainExecutionError`。

### 2.5 领域结果存储

领域结果独立存放于 `var/domain-results`，采用：

- 确定性结果 ID；
- 临时目录写入与原子提交；
- 结果文件 SHA-256；
- 语义摘要；
- 来源结构摘要；
- 文档、解析运行、Domain Pack 与运行时身份绑定；
- 同 ID 不同语义拒绝；
- 读取时反向校验来源结构、来源元素和证据。

运行时升级后，历史结果仍可读取和验证。历史结果不会因为当前运行时实现摘要变化而被错误
判定为损坏。

### 2.6 LabelU 审核桥接

实现 `labelu-json-v1` 适配接口：

- 按页面导出领域对象；
- 同页关系放入页面任务；
- 跨页关系独立保留；
- 导出绑定领域结果语义摘要和适配包版本；
- 重复导出幂等；
- 回传对象与关系必须使用适配包声明的标签；
- 回传元素必须来自原始文档；
- 回传必须与原导出及当前领域结果摘要一致；
- 审核记录原子提交并校验文件摘要；
- 路径 ID 与命名空间严格校验。

本阶段交付的是审核数据协议和服务端桥接，不包含完整 LabelU 前端部署。

### 2.7 首批验证包

提供两个声明式验证包：

- `generic-document@0.2.0`：章节、段落、插图和表格；
- `education-content@0.1.0`：作为复杂关系验证包，验证对象分类、关系恢复、验证器和审核。

第二个包只是首个验证领域，不改变主项目的通用定位。

### 2.8 API 与 CLI

API 新增：

- `GET /v1/domain-packs`；
- `POST /v1/domain-packs/install`；
- `POST /v1/domain-packs/{pack_id}/{version}/activate`；
- `POST /v1/domain-packs/{pack_id}/deactivate`；
- `DELETE /v1/domain-packs/{pack_id}/{version}`；
- `POST /v1/domain/apply`；
- `GET /v1/domain-results/{domain_result_id}`；
- `POST /v1/domain-results/{domain_result_id}/review/export`；
- `POST /v1/domain-reviews`。

管理和审核读取接口要求摘要化令牌；写操作还要求显式打开
`DI_ENABLE_DOMAIN_PACK_WRITES`。默认配置为拒绝管理访问和禁止写入。

CLI 提供相同生命周期和领域应用、结果读取、审核导出与回传能力。本地 CLI 写操作仍必须
显式打开写入开关。

## 3. 自审发现与修复

### 3.1 历史兼容性误锁

最初实现对每次读取都强制检查当前引擎兼容范围。这会导致运行时升级后旧结果无法读取，
也可能让旧包无法卸载。已区分：

- 新执行和激活：强制当前兼容性；
- 历史结果读取、列表和卸载：验证内容完整性，但不以当前兼容范围阻断。

### 3.2 原始异常信息泄露

最初回退结果直接记录 `str(exception)`，可能泄露路径、服务响应或内部配置。已改为稳定、
脱敏的失败消息；原异常仅保留在异常链和服务端诊断范围。

### 3.3 审核导出非幂等及非原子

最初同一导出 ID 会因 `created_at` 不同发生内容冲突，目录写入中断也可能留下半成品。现已：

- 已存在同源导出时返回原记录；
- 使用临时目录完整写入后原子重命名；
- 并发提交后重新验证内容。

### 3.4 审核记录路径越界

审核记录 ID 最初没有在存储层再次校验。现已使用统一安全 ID 校验，并只允许固定的
`exports` 与 `submissions` 命名空间。

### 3.5 跨页审核关系丢失

最初 LabelU 页面任务只保留同页关系。现增加 `cross_page_relations`，避免跨页领域关系在
审核导出时被静默丢弃。

### 3.6 导入循环

独立运行阶段基准时发现：

`domain_runtime -> services.store -> services.__init__ -> bootstrap -> domain_runtime`

形成包级循环依赖。pytest 的导入顺序偶然掩盖了该问题。现将 bootstrap 导出改为延迟加载，
并加入独立直接导入和 wheel 任意目录导入验证。

### 3.7 适配规则约束不足

对象规则的 `base_types` 现必须至少声明一个类型，并且必须是该领域对象在本体中允许的基础
类型子集，防止规则悄然扩大作用范围。

## 4. 验证结果

冻结前执行：

- 110 项自动测试；
- 分支覆盖率门禁 80%；
- Phase 1、2、3、4 阶段验证；
- AST、行长、危险调用、公开注解和核心领域中立静态检查；
- 两个验证包摘要与复制一致性检查；
- 8 项 Phase 4 确定性基准；
- wheel 构建、安装后 CLI 和任意工作目录导入；
- 完整 ZIP 哈希和独立解压复验。

最终数字以同目录 `verification.json`、`benchmark_results.json` 和发行包内测试结果为准。

## 6. 下一阶段入口

Phase 5 应实现 Rill Shadow：

- 只观察，不改变生产路线；
- 接收解析、匹配、结构和领域运行信号；
- 记录静态策略与 Rill 建议的差异；
- 建立离线回放、延迟反馈和严重错误惩罚；
- 禁止 Route Assist 和 boundedAuto；
- 证明不会提高 P0/P1 错误后，才允许进入后续 Assist 阶段。

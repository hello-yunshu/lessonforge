# Phase 6 实施、冻结与自审报告

## 1. 阶段范围

本阶段实现Rill Assist的候选资格与Tier 1受控执行。它不是自动驾驶层，也不开放boundedAuto。生产环境默认配置仍拒绝Assist写入与执行。

## 2. 已实现能力

- 专家反馈证明与来源分级；
- Reference Runtime、合成数据和未固定产物摘要的资格否决；
- Rill与静态基线准确率对照、P0/P1错误接受门禁、动作覆盖率门禁；
- 资格报告绑定feature schema、Runtime身份、model/state generation以及Runtime、模型、Handler摘要；正式资格还要求Runtime `inspect`回报其实际加载的三类产物摘要并与宿主固定值完全一致；
- 有期限、有人类批准、有限速的不可变激活；
- retry、高分辨率、第二解析器、专家解析器的附加候选运行；
- 人工审核优先级与隔离队列；
- 绑定漂移告警、不可暂停native-pdf、可人工恢复的解析器熔断；
- 撤销、过期、漂移、Runtime身份变化、摘要变化和实时回放退化的即时阻断；
- API、CLI、JSON Schema、配置、审计存储与发行门禁。

## 3. 强制安全边界

- `boundedAuto=false`为模型常量和策略文件常量；
- Assist不修改标准库、黄金数据、已有解析结果、结构结果、领域结果或审核结论；
- Parser动作只创建带父运行ID的候选结果；
- 队列动作只创建不可变任务；
- Reference后端及测试夹具不得激活生产Assist；
- 资格与激活均有期限，且激活不能超出资格有效期；
- 解析器暂停只能由操作员执行，必须绑定已验证漂移告警；
- `native-pdf`作为确定性回退不得暂停。

## 4. 自审发现与修复

1. Runtime摘要验证方法曾误放在Protocol中，已移至真实子进程客户端；
2. 资格报告最初允许缺少模型或Handler摘要，现合格报告必须三摘要齐全；
3. 激活曾使用零摘要占位，现缺失即拒绝；
4. 同一重放数据重复资格因动态过期时间可能冲突，现资格ID显式绑定生成时点；
5. 小时限流最初存在并发竞争，现执行、复核、限流和提交共用激活文件锁；
6. 安全或限流阻断曾只抛异常不留审计，现生成不可变BLOCKED记录；
7. 实时安全只比较静态基线，现同时要求达到资格最低准确率；
8. 阶段计划中的异常模型暂停最初缺失，现实现可逆解析器熔断；
9. 暂停若直接复用普通激活验证会被漂移门禁挡住，现仅熔断管理允许在漂移状态下运行；
10. 显式parser_id曾可能绕过熔断，现显式和自动路由均统一检查；
11. 仅由宿主配置三类摘要不能证明Runtime实际加载了相应产物，现资格和激活都要求Runtime `inspect`提供`artifactDigests`证明，缺失或不一致时保持Shadow。

## 5. 冻结结论

Phase 6工程实现可作为Phase 7持续学习与MLOps开发基线。由于当前包中没有真实专家生产反馈、正式签名Rill模型/Handler资格报告和真实复杂文档压力结果，本包不自动创建生产激活，也不宣称已取得生产Assist资格。

# Phase 7 实施、冻结与自审报告

## 1. 阶段范围

Phase 7 实现持续学习与 MLOps 治理，但不在核心进程中执行任意训练代码，也不自动发布模型。DVC 与 MLflow 作为外部可替换系统，通过不可变摘要、修订号、运行ID和人工证明接入。

## 2. 已实现能力

- Rill 信号驱动的主动学习排序，包含多策略分歧、低置信度、规则冲突、领域回退和漂移上下文；
- 已送审样本、已获专家证明样本不重复进入新批次；
- DVC 数据快照记录：角色、仓库修订、数据摘要、清单摘要、Schema摘要、父版本及专家批准；
- 训练、验证、黄金、挑战数据角色隔离；
- MLflow 运行证明：experiment/run ID、跟踪地址摘要、参数摘要、模型摘要、源码提交及数据快照；
- Candidate 注册仅接受 FINISHED 运行，模型摘要和源码提交必须与 MLflow 证明一致；
- 黄金集与挑战集为独立、专家确认、不可变快照，并禁止与训练数据重叠；
- 离线门禁覆盖准确率、P0/P1、严重错误、标准误匹配、关键值、关系、延迟、成本和文档族回退；
- Candidate → Shadow → Champion 的顺序状态机；
- Champion 必须同时绑定通过的离线评测、通过的 Shadow 验证和新的人工批准；
- 前一 Champion 自动保留为 Rollback，一次操作可交换 Champion 与 Rollback；
- Candidate 完整血缘读取，包括 DVC、MLflow、评测、Shadow、批准与别名变更；
- API、CLI、JSON Schema、Docker配置、阶段基准和发行门禁。

## 3. 强制边界

- `boundedAuto=false`，没有配置项可以开启；
- 主动学习只排序，不把模型结论直接升级为训练真值；
- MLOps 核心只保存摘要和外部运行证明，不执行训练脚本、Shell或任意模型文件；
- 注册写入和发布别名是两个独立开关；
- Candidate 不得跳过黄金集和挑战集；
- Champion 不得跳过 Shadow 验证和人工批准；
- 发行包不包含任何已激活的生产 Candidate、Champion 或 Rollback 状态。

## 4. 自审发现与修复

1. 主动学习批次ID最初未绑定排除集合和漂移集合，已纳入完整上下文摘要；
2. 别名状态最初使用数据文件和摘要文件两次写入，已改为单文件原子信封；
3. Shadow 别名最初可立即晋升 Champion，已增加不可变灰度验证和第二次人工批准；
4. 训练运行最初可绑定黄金或挑战快照，现明确拒绝；
5. 黄金集和挑战集最初可能实际指向同一数据摘要，现要求数据互斥；
6. 保护集最初可能与训练血缘重叠，现于评测前拒绝；
7. Shadow 最初只要求一个样本，现默认至少100个样本；
8. Shadow 与离线评测最初未对P1和严重错误实行绝对门禁，现零容忍；
9. 挑战集默认只要求不回退，现默认要求至少0.001的可验证提升；
10. 业务门禁最初使用普通 `ValueError`，现使用稳定的 `MLOPS_GATE_BLOCKED`；
11. 已进入主动学习批次但尚未审核的样本可能在新增数据后重复排队，现保持去重；
12. 覆盖率初始精确值为79.85%，补齐关键失败分支后提升至80.16%；
13. Phase 6兼容门禁最初把项目版本写死为0.6.0，现改为不得低于0.6.0；
14. 基线候选与基线指标最初可能不成对，现于请求Schema层拒绝；
15. Shadow时间窗、MLflow重复快照和非有限指标最初可能在服务内部才失败，现于API输入层稳定拒绝。

## 5. 验证结果

- 自动测试：178项全部通过；
- 精确综合覆盖率：80.16%；
- Phase 1—7兼容门禁：全部通过；
- Phase 7确定性基准：9/9通过；
- 静态安全检查：通过；
- wheel构建、任意目录导入和安装后CLI：通过；
- 完整ZIP独立解压、源码哈希、测试和Phase 7门禁：通过；
- Ruff与Mypy固定在CI，当前离线环境未安装，故不声明本地通过。

这些结果证明工程边界和确定性回归，不代表已经训练或发布真实生产模型。

## 6. 冻结结论

0.7.0 可作为 Phase 8 多领域扩展的工程基线。生产发布仍需真实DVC仓库、正式MLflow服务、真实黄金/挑战集、模型训练产物、正式Shadow流量、双人批准、压力测试与许可证处理。

# Phase 9：1.0冻结实施、冻结与自审报告

## 1. 结论

`document-intelligence 1.0.0` 已完成工程契约冻结。冻结通过不等于生产资格通过：真实多领域黄金集、外部解析器固定产物、规模与并发证据、Ruff/Mypy正式CI证据以及PyMuPDF发行许可仍是明确阻断项。

## 2. 冻结范围

机器清单冻结以下10个契约面：

1. 核心Schema；
2. Parser SDK；
3. Domain Pack SDK；
4. Rill事件协议；
5. 已存在REST操作；
6. 1.x版本语义；
7. 权限与默认关闭边界；
8. 发布门禁；
9. 回滚行为；
10. 不可变审计记录格式。

冻结清单中的每个契约都具有独立SHA-256，清单自身再具有总摘要。加载时同时校验子契约摘要和总摘要；此外，代码内置独立的v1清单信任锚，防止攻击者同时替换清单内容并重算摘要形成一份“自洽但伪造”的冻结基线。

## 3. 实现

### 3.1 冻结运行时

新增 `document_intelligence.freeze`：

- `FreezeManifest`：冻结清单严格Schema；
- `FrozenContract`：单个契约及其规范化摘要；
- `FreezeService`：读取、校验和实时兼容验证；
- `discover_api_operations()`：使用AST直接发现API源码中实际声明的路由与HTTP方法，验证既有冻结操作没有被删除或改名；
- `FreezeVerification`：差异报告；
- `FreezeBenchmarkReport`：Phase 9门禁结果。

提供：

- API：`GET /v1/contracts/freeze`；
- CLI：`freeze-inspect`、`freeze-verify`；
- JSON Schema：冻结清单、验证和基准报告。

### 3.2 版本与Domain Pack

- 项目版本：`1.0.0`；
- Domain Runtime：`1.0.0`；
- 文档族检测器：`1.0.0`；
- 内置Domain Pack引擎兼容范围：`>=0.4,<2.0`；
- 核心Schema继续保持`1.1`，避免伪造无必要的数据迁移。

### 3.3 权限冻结

以下写入和发布开关默认均为`false`：标准库、Domain Pack、文档族检测、Rill Shadow、Rill Assist、Assist执行、MLOps登记、MLOps发布。对应权限域继续使用独立令牌摘要。`boundedAuto`保持硬编码`false`。

### 3.4 回滚冻结

- Assist激活可撤销且不删除审计；
- 解析器熔断可恢复，`native-pdf`不得暂停；
- Champion切换保留Rollback；
- Champion必须通过离线评测、Shadow和人工批准；
- 回滚只原子切换别名，不修改模型产物；
- Rill故障回退至确定性非Rill路径。

## 4. 实施后自审与修复

1. **空状态导入副作用**：API导入曾创建`var/domain-packs/state.json`。改为注册表空状态延迟落盘；只有激活或停用发生时才写状态。
2. **重复读取状态**：`activate()`内部曾连续读取两次状态，已删除重复调用。
3. **审计模型选择错误**：最初误把瞬时`MatchResult`和API输入`LabelUReviewSubmission`列为落盘审计，现改为真实持久记录并验证ID字段。
4. **冻结脚本可覆盖风险**：生成脚本改为默认只验证；同一稳定主版本不能直接覆盖清单。
5. **补丁版本矛盾**：项目版本不再进入冻结契约摘要；实时版本按`>=1.0.0,<2.0.0`校验，允许不改变契约的安全补丁。
6. **REST扩展语义**：已冻结操作必须保留；1.x新增隔离操作可作为向后兼容扩展。
7. **Domain Pack 1.0兼容**：六个内置包的旧`<1.0`上限已调整为`<2.0`，并保留历史不兼容包可枚举、不可执行、可安全卸载的行为。
8. **CLI重复参数**：修复`rill-assist-attest`重复注册`file`位置参数的问题。
9. **顶层清单元数据**：实时验证除了逐契约摘要，还检查清单顶层元数据摘要，防止只改生产资格或阻断项而不被发现。
10. **清单自洽替换风险**：加入代码内独立信任锚；即使替换者同步重算全部SHA-256，也无法把新清单冒充为既有v1冻结基线。
11. **路由验证来源不足**：不再只相信清单自身列出的REST操作，改为AST扫描`api/main.py`中的真实装饰器声明并与冻结操作逐项比较。

## 5. 冻结门禁

- 冻结清单与实时契约完全一致；
- 1.x版本范围正确；
- 已冻结REST操作全部存在；
- 六个内置Domain Pack可在1.0 Runtime安装和复核；
- 所有写入权限默认关闭；
- 发布包不包含运行态记录；
- boundedAuto为false；
- 全阶段兼容、测试、覆盖率、静态安全、wheel和ZIP独立复验通过。

## 6. 冻结判断

- **工程契约1.0冻结：通过**；
- **作为后续1.x维护基线：通过**；
- **生产质量资格：不通过，待外部证据**；
- **boundedAuto：未开放且不属于1.x默认能力**。
